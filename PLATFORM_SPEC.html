Platform Specification & Master Build Prompt

A full-stack competitive intelligence platform that scrapes every NJ dispensary's deals, pricing, and new drops in near real-time — organized by geography and built to sell.

Version 1.0
State New Jersey (21 counties)
Date August 2026
Stack Python / FastAPI / Next.js / PostGIS
01

Vision & Use Cases

An upgraded replacement for Lit Alerts and Pistil Data, built NJ-first. Where those tools are broad and national, this platform is hyper-local — every discount, every price drop, every new product drop, filtered by radius, county, or city. Built for marketing directors, expandable into a SaaS sold to competing dispensaries and MSOs.

Primary Use Cases

WhoWhat They NeedPlatform Feature
Marketing Director (you)Know what competitors are running before planning your own promosLive deal feed, county/radius filter, alert on new deals
Dispensary GMBenchmark pricing against nearby dispensariesPrice comparison report, neighbor radius view
MSO Marketing TeamTrack deal patterns across an entire regionRegional market report, trend charts, weekly digest
Cannabis InvestorUnderstand competitive pricing and deal frequencyMarket overview reports, historical data export
Brand / VendorSee which dispensaries are promoting their productsBrand-level deal tracking, product mention alerts

What Makes This Different

Lit Alerts sends SMS blasts for deals nationally — no geographic intelligence, no history, no competitive context. Pistil Data sells enterprise reports at enterprise prices, not NJ-specific, not real-time. This platform is NJ-only, real-time, geo-filtered, and built from a marketing director's lens — not a data analyst's.

Data Sources & Scraping Strategy

Most NJ dispensaries don't run custom menus — they embed one of a handful of platforms. Build scrapers for the platforms, not per-dispensary. The NJ CRC provides the authoritative list of licensed dispensaries as the master registry.

NJ CRC — Master Registry

Start here. The NJ Cannabis Regulatory Commission publishes a list of all licensed dispensaries at nj.gov/cannabis/businesses/licensees/. Scrape this weekly to catch new licenses. This is your source of truth for the dispensary table.

Database Schema

PostgreSQL 15 + PostGIS. Geo columns use GEOGRAPHY(POINT, 4326) so PostGIS handles radius queries natively. All timestamps are UTC.

Core Tables — PostgreSQL + PostGIS
-- Multi-tenant organizations
CREATE TABLE organizations (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name        TEXT NOT NULL,
  plan        TEXT DEFAULT 'free',   -- free | pro | enterprise
  created_at  TIMESTAMPTZ DEFAULT now()
);

-- Users
CREATE TABLE users (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id        UUID REFERENCES organizations(id),
  email         TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  role          TEXT NOT NULL DEFAULT 'viewer',
  name          TEXT,
  created_at    TIMESTAMPTZ DEFAULT now(),
  last_login    TIMESTAMPTZ
);

-- Master dispensary registry
CREATE TABLE dispensaries (
  id               UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name             TEXT NOT NULL,
  slug             TEXT UNIQUE,
  license_number   TEXT,           -- NJ CRC license
  address          TEXT,
  city             TEXT,
  county           TEXT,
  zip              TEXT,
  lat              NUMERIC(10,7),
  lng              NUMERIC(10,7),
  geom             GEOGRAPHY(POINT, 4326), -- for PostGIS radius queries
  weedmaps_id      TEXT,
  leafly_slug      TEXT,
  jane_store_id    TEXT,
  dutchie_id       TEXT,
  treez_id         TEXT,
  dispense_slug    TEXT,
  primary_platform TEXT,   -- jane | dutchie | weedmaps | leafly | custom
  website          TEXT,
  phone            TEXT,
  instagram        TEXT,
  status           TEXT DEFAULT 'active',
  med_only         BOOLEAN DEFAULT FALSE,
  created_at       TIMESTAMPTZ DEFAULT now(),
  updated_at       TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX idx_dispensaries_geom ON dispensaries USING GIST(geom);
CREATE INDEX idx_dispensaries_county ON dispensaries(county);

-- Active deals
CREATE TABLE deals (
  id                    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  dispensary_id         UUID REFERENCES dispensaries(id),
  source_platform       TEXT,    -- jane | dutchie | weedmaps | leafly
  external_id           TEXT,    -- ID from source platform
  title                 TEXT,
  description           TEXT,
  deal_type             TEXT,    -- percent_off | dollar_off | bogo | bundle | first_time | daily
  discount_value        NUMERIC, -- 20 for "20% off", 5 for "$5 off"
  discount_unit         TEXT,    -- percent | dollar
  minimum_purchase      NUMERIC,
  applicable_categories TEXT[], -- {flower, edibles, concentrates}
  applicable_brands     TEXT[],
  day_of_week           TEXT[], -- null=all days, or {monday, tuesday}
  starts_at             TIMESTAMPTZ,
  ends_at               TIMESTAMPTZ,
  is_active             BOOLEAN DEFAULT TRUE,
  raw_text              TEXT,   -- original scraped text for re-parsing
  first_seen_at         TIMESTAMPTZ DEFAULT now(),
  last_seen_at          TIMESTAMPTZ DEFAULT now(),
  created_at            TIMESTAMPTZ DEFAULT now()
);

-- Deal change history
CREATE TABLE deal_history (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  deal_id      UUID REFERENCES deals(id),
  change_type  TEXT, -- created | modified | deactivated | reactivated
  old_data     JSONB,
  new_data     JSONB,
  changed_at   TIMESTAMPTZ DEFAULT now()
);

-- Menu items (product catalog)
CREATE TABLE menu_items (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  dispensary_id UUID REFERENCES dispensaries(id),
  external_id   TEXT,
  name          TEXT,
  brand         TEXT,
  category      TEXT,    -- flower | edible | concentrate | vape | tincture | topical | preroll
  subcategory   TEXT,
  thc_percent   NUMERIC(5,2),
  cbd_percent   NUMERIC(5,2),
  weight        NUMERIC,  -- grams
  current_price NUMERIC(10,2),
  sale_price    NUMERIC(10,2),
  is_active     BOOLEAN DEFAULT TRUE,
  first_seen_at TIMESTAMPTZ DEFAULT now(),
  updated_at    TIMESTAMPTZ DEFAULT now(),
  UNIQUE(dispensary_id, external_id)
);

-- Price change tracking
CREATE TABLE price_changes (
  id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  item_id        UUID REFERENCES menu_items(id),
  dispensary_id  UUID REFERENCES dispensaries(id),
  old_price      NUMERIC(10,2),
  new_price      NUMERIC(10,2),
  change_amount  NUMERIC(10,2),
  change_pct     NUMERIC(6,2),
  change_type    TEXT,    -- increase | decrease
  detected_at    TIMESTAMPTZ DEFAULT now()
);

-- User-defined alert rules
CREATE TABLE alerts (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id       UUID REFERENCES users(id),
  org_id        UUID REFERENCES organizations(id),
  name          TEXT NOT NULL,
  trigger_type  TEXT, -- new_deal | price_drop | new_product | deal_change | deal_expired
  filter_config JSONB, -- geo filter, category, brand, dispensary list
  channels      TEXT[], -- {email, sms, webhook}
  is_active     BOOLEAN DEFAULT TRUE,
  created_at    TIMESTAMPTZ DEFAULT now()
);

Geographic Radius Query

PostGIS — Radius Search Example
-- All dispensaries within 10 miles of a lat/lng with active deals
SELECT
  d.name, d.city, d.county,
  ST_Distance(d.geom, ST_MakePoint(:lng, :lat)::geography) / 1609.34 AS miles,
  COUNT(deals.id) AS active_deals
FROM dispensaries d
LEFT JOIN deals ON deals.dispensary_id = d.id AND deals.is_active = TRUE
WHERE ST_DWithin(d.geom, ST_MakePoint(:lng, :lat)::geography, :meters)
GROUP BY d.id
ORDER BY miles;

Scraping Engine

Celery Beat handles scheduling. Redis is the broker. Each platform has a dedicated scraper class. Playwright handles JS-heavy or anti-bot sites. aiohttp handles clean REST/GraphQL APIs.

Scraping Architecture
# Scrape schedule by platform priority
jane_scraper      → every 2h  (REST, fast, clean)
dutchie_scraper   → every 2h  (GraphQL, fast)
weedmaps_scraper  → every 3h  (REST, rate-limit sensitive)
leafly_scraper    → every 4h  (REST, rate-limit sensitive)
treez_scraper     → every 3h  (REST with page-sourced key)
custom_scraper    → every 6h  (Playwright, slowest)
nj_crc_scraper    → weekly     (master dispensary list)

# Change detection flow (every scrape run):
1. Fetch current deals from platform API
2. Compare to deals table (match on dispensary_id + external_id)
3. New deal found → INSERT + emit WebSocket event + check alerts
4. Deal modified → UPDATE + INSERT deal_history record
5. Deal no longer returned → mark is_active=FALSE, record deactivation

# Price change detection (every menu scrape):
1. Fetch current menu from platform
2. Compare current_price to menu_items.current_price
3. If changed → UPDATE menu_items + INSERT price_changes record
4. If decreased → emit WebSocket + check price_drop alerts

# New product detection:
1. Product not in menu_items for this dispensary → INSERT
2. Emit new_product event, check new_product alerts

Anti-Bot Approach

TechniqueWhen Applied
Randomized 2–5s delay between requestsAll scrapers
Rotating User-Agent pool (20+ real browser strings)All scrapers
Playwright with real Chromium fingerprintWeedmaps, custom sites
Residential proxy rotation (optional)If any source starts blocking
Respectful crawl rate — never exceed 1 req/2s per domainAlways
Retry with exponential backoff on 429/503All scrapers

Alert System

Users configure rules. When a scrape run detects a match, the alert fires through configured channels within minutes of detection.

Alert Rule Config Schema (JSONB)
# filter_config column in alerts table
{
  // Geographic filter (one of these)
  "geo": {
    "mode": "radius",       // radius | county | city | dispensary_list
    "lat": 40.7282, "lng": -74.0776, "miles": 10
  },

  // Deal filters (all optional)
  "categories": ["flower", "concentrate"],
  "brands": ["Jeeter", "Cookies"],
  "min_discount_pct": 20,   // only alert if >= 20% off
  "deal_types": ["percent_off", "bogo"],
  "dispensary_ids": []       // empty = all dispensaries matching geo
}

# Trigger types
new_deal       # new deal posted matching filters
price_drop     # any price decrease (optionally: min pct)
new_product    # new SKU added to menu matching category/brand
deal_change    # existing deal modified (value, dates, conditions)
deal_expired   # tracked deal ended

# Channels
email   # via Resend
sms     # via Twilio
webhook # POST JSON to a URL (for Slack, custom integrations)

--- DATA SOURCES ---
Build one scraper class per platform in scrapers/ directory.
Each scraper must: fetch data, normalize to schema, compare to DB, detect changes,
save changes, emit events, log job result.

JANE (iheartjane.com) — Priority: HIGH
  Base: https://api.iheartjane.com/v1/
  Discovery: GET /stores?state=NJ (returns all NJ stores with jane store_id)
  Deals: GET /stores/{store_id}/specials
  Menu: GET /stores/{store_id}/menu
  Auth: none required for public endpoints
  Schedule: every 2 hours

DUTCHIE — Priority: HIGH
  Detect by: embedded script tag src containing dutchie.com or dutchie iframe
  GraphQL endpoint: https://dutchie.com/api/retailer/graphql
  Also try: https://plus.dutchie.com/plus/2021-07/graphql
  Get retailer_id from the embed URL or script tag
  Query: GetMenu(retailerId) → products with variants.price + specialPricing + specials
  Schedule: every 2 hours

WEEDMAPS — Priority: HIGH
  Base: https://api-g.weedmaps.com/discovery/v1/
  NJ listings: GET /listings?filter[state_abv]=NJ&filter[type]=dispensary&page[size]=100
  Deals/promos: GET /listings/{wmid}/promotions
  Menu: GET /listings/{wmid}/menu_items?include=price_tiers
  Headers required: User-Agent (real browser UA), Referer: https://weedmaps.com
  Schedule: every 3 hours. Respect rate limits with 2-3s delays.

LEAFLY — Priority: MEDIUM
  Base: https://consumer-api.leafly.com/api/
  NJ dispensaries: GET /dispensary_info/v2?state_abbr=NJ&take=50&skip=0
  Deals: GET /dispensary_info/v2/{slug}/deals
  Menu: GET /strain_playlists/v2?dispensary_slug={slug}
  Headers: app_type=web, x-user-timezone: America/New_York
  Schedule: every 4 hours

TREEZ — Priority: MEDIUM
  Detect by: window.treezConfig in page source (use Playwright to extract)
  Extract apiKey and retailer_id from page JS
  Base: https://api.treez.io/catalog/v3/
  Menu: GET /catalog/{retailer_id}/menu
  Specials: GET /catalog/{retailer_id}/specials
  Auth header: x-api-key: {extracted key}
  Schedule: every 3 hours

DISPENSE — Priority: WATCH
  Base: https://api.dispense.us/v1/
  Store slug found in embedded script or meta tags
  Menu: GET /menu?store={slug}
  Schedule: every 4 hours

NJ CRC REGISTRY — Priority: CRITICAL (weekly)
  Source: https://www.nj.gov/cannabis/businesses/licensees/
  Scrape with Playwright, extract all active licenses, update dispensaries table
  Geocode any new entries via Google Maps Geocoding API
  Schedule: weekly (Sunday midnight)

--- CHANGE DETECTION LOGIC ---
After every scrape run, for each deal returned from source:
  1. Look up in deals table by (dispensary_id, source_platform, external_id)
  2. Not found → INSERT new deal, set is_active=true, record deal_history(created)
     → emit WebSocket event: deal.new
     → check all active alerts with trigger_type=new_deal
  3. Found and data changed → UPDATE deals, record deal_history(modified)
  4. Previously seen but NOT returned this scrape → set is_active=false
     → record deal_history(deactivated) → emit WebSocket: deal.expired

For each menu_item returned:
  1. Look up by (dispensary_id, external_id)
  2. Not found → INSERT, emit WebSocket: product.new
     → check alerts with trigger_type=new_product
  3. Found, price changed → UPDATE, INSERT price_changes record
     → if price decreased: emit WebSocket: price.drop
     → check alerts with trigger_type=price_drop

--- AUTH SYSTEM ---
POST /api/v1/auth/login → returns {access_token, refresh_token, user}
  access_token: JWT signed HS256, expires 15min
  refresh_token: JWT signed HS256, expires 30d, stored in httpOnly cookie
POST /api/v1/auth/refresh → validates refresh_token, returns new access_token (rotate refresh)
POST /api/v1/auth/logout → blacklist refresh token in Redis with TTL = remaining life
All protected routes: Bearer token in Authorization header

Roles and permissions:
  super_admin: everything, including cross-org access and scraper management
  admin: full org access, user management, all reports, all alerts
  manager: own alerts, own reports, view all data
  analyst: view all data, export reports, no alert modification
  viewer: view live feed and current deals only, no exports, no alerts

All under /api/v1/. Auth required on all except /auth/*.
Return paginated lists with {data, total, page, per_page}.
Support ?county=, ?city=, ?category=, ?deal_type=, ?min_discount= on deal endpoints.

--- ALERT SYSTEM ---
After change detection, for each new deal / price drop / new product:
  1. Query all active alerts matching: trigger_type AND geo filter AND category/brand filters
  2. For each matching alert: compose message, dispatch to each channel:
     email: POST to Resend API with HTML template
     sms: POST to Twilio Messages API
     webhook: POST JSON payload to alert.filter_config.webhook_url
  3. INSERT alert_events record

Alert filter_config shape:
  geo: {mode: radius|county|city|list, lat, lng, miles, county, city, dispensary_ids[]}
  categories: string[] (flower, edible, concentrate, vape, preroll, tincture, topical)
  brands: string[]
  min_discount_pct: number
  deal_types: string[]

--- REPORT TYPES ---
Implement each report as a separate function returning structured data.
All reports accept: {date_from, date_to, county, city, dispensary_ids[], categories[]}

live_deal_snapshot: all is_active=true deals, organized by county+city, with dispensary info
deal_history: all deals in date range with changes timeline
price_changes: all price_changes in date range, grouped by item + dispensary
competitor_deal_frequency: COUNT(deals) per dispensary per day, breakdown by deal_type
market_discount_depth: AVG(discount_value) by category and county for date range
new_drops: menu_items WHERE first_seen_at in date range
day_of_week_pattern: COUNT(deals) by day_of_week per dispensary
alert_history: alert_events in date range for this user

All reports exportable to CSV. Selected reports exportable to PDF via WeasyPrint.
Reports can be saved as configurations and scheduled (daily|weekly|monthly).
Scheduled reports run via Celery Beat and email results to configured recipients.
